# RAG 평가 파이프라인 구성 과제

이전에 구성한 RAG에 평가 프레임워크를 연결합니다.
질문 실행 → 검색·답변 평가 → 결과 저장까지 구성하고, 실제 결과에서 확인한 실패 원인을 설명해주세요.

## 1. LLM Evaluation 조사·정리

아래 영상을 참고해 다음 내용을 자신의 말로 정리해주세요.

1. **LLM Evaluation의 목적은 무엇인가요?** 평가 결과를 통해 어떤 판단을 내리려고 하나요?
2. **본인이 만든 RAG가 잘 동작한다는 기준은 무엇인가요?** 성공과 실패를 구체적인 예로 설명해주세요.
3. **그 기준을 확인하려면 무엇을 평가해야 하나요?** 검색 결과와 생성 답변에서 각각 확인할 내용을 정리해주세요.
4. **선택한 평가 지표와 LLM Judge가 그 기준을 충분히 확인할 수 있나요?** 놓칠 수 있는 문제도 설명해주세요.

평가 프레임워크는 **Ragas를 출발점으로 제안합니다.**
다른 평가 프레임워크와 검색 구성도 찾아보고, 본인의 RAG에 적용할 방식과 선택 이유를 기록해주세요.

- [Stanford CME295 — LLM Evaluation](https://www.youtube.com/watch?v=8fNP4N46RRo)

## 2. 평가 질문과 기준 준비

이전 과제에서 사용한 RAG와 데이터를 평가 대상으로 사용합니다.
질문은 **최소 5개** 준비해주세요.

| 유형 | 최소 문항 수 | 기대하는 동작 |
|---|---:|---|
| 문서로 답할 수 있는 질문 | 3개 | 필요한 근거를 찾아 정확하고 충분하게 답변 |
| 문서로 답할 수 없는 질문 | 1개 | 확인할 수 없다고 안내 |
| 일부만 답할 수 있는 질문 | 1개 | 확인 가능한 내용과 확인 불가능한 내용을 구분 |

각 질문에는 기대 답변, 근거 문서·페이지 또는 위치, 답변 가능 여부를 함께 기록합니다.
기대 답변과 평가용 라벨은 RAG의 검색 문서나 답변 생성 입력에 넣지 않습니다.

## 3. 평가 파이프라인 구성·실행

1. 문서, 청킹, 검색 방식, 검색 개수, 생성 모델과 프롬프트를 기록합니다.
2. 선택한 평가 프레임워크를 기존 RAG에 연결합니다.
3. **검색 지표와 생성 지표를 각각 하나 이상** 선택하고, 무엇을 어떤 입력으로 평가하는지 설명합니다.
4. 준비한 질문을 실행해 검색 결과, 실제 전달 컨텍스트와 최종 답변을 저장합니다.
5. 선택한 지표로 평가하고 문항별 점수와 평가 이유를 저장합니다.
6. 사람이 원문과 답변을 대조해 질문이 해결됐는지 판정합니다.

지표는 앞에서 정한 성공 기준과 데이터에 맞게 선택합니다.
적용할 수 없는 문항은 값을 임의로 채우지 말고 적용 불가 사유를 기록해주세요.

별도로 실행한 검색 결과가 생성 모델에 전달된 컨텍스트와 같다고 가정하지 않습니다.
관리형 서비스에서 전체 컨텍스트를 확인하기 어렵다면 그 한계를 밝히고, 확보한 기록으로 평가할 수 있는 지표를 선택합니다.

## 4. 결과 분석

대표 실패 사례 하나를 골라 다음 내용을 설명해주세요.

- 원문에는 답변에 필요한 근거가 있었나요?
- 검색이 그 근거를 찾았나요?
- 생성 모델은 전달된 근거를 사용해 질문에 충분히 답했나요?
- 답변 가능 여부를 올바르게 판단했나요?
- 사람의 판정과 자동 평가 결과는 일치했나요?
- 무엇을 먼저 개선해야 하나요?

실패가 발견되지 않았다면 통과 판단의 근거와 아직 확인하지 못한 상황을 설명합니다.
개선안을 적용해 전후를 비교하는 작업은 선택 사항입니다.
