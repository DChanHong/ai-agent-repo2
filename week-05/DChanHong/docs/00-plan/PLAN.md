# 공모주 청약 판단 에이전트 개발 계획

사용자가 기간을 입력하면 일반청약 일정이 겹치는 종목 전체를 보여준다. 청약 마감이 빠른 최대 3개 종목을 상세 분석하고, 마감일이 같으면 회사명 가나다순으로 정렬한다. 종목별 결과에는 청약 판단, 결정적인 근거, 확인하지 못한 조건을 함께 적는다.

## 실행 환경과 초기값

| 항목 | 설정 | 선택 이유 |
|---|---|---|
| 실행 환경 | Python 3.13, uv, OpenAI Agents SDK, 단일 에이전트 | 모델이 조회 결과에 따라 다음 도구를 선택하고, 실행 기록에서 그 선택을 검증할 수 있다. |
| 모델 | `gpt-6-luna` | 공시 선택과 근거 해석에는 도구 호출 모델을 쓰고, 금액 계산은 Python에 맡긴다. 반복 평가 비용을 고려한 초기값이다. |
| 반복 한도 | 사용자 요청당 `max_turns=12` | 최대 3개 종목의 공시 확인과 최종 비교에 필요한 여유를 둔다. SDK의 한 턴은 모델 호출 한 번이며 한 턴에 여러 도구를 호출할 수 있다. |

요청이 해결되면 즉시 종료한다. 자료가 부족하면 확인한 범위와 보류 사유를 반환한다. 반복 한도에 걸리면 실행을 목표 미달성으로 기록한다. 모델과 턴 한도는 아래 세 가지 실행을 평가한 뒤 조정한다. [SDK 실행 가이드](https://openai.github.io/openai-agents-python/running_agents/)

## 도구 3개

| 도구 | 입력 | 반환할 내용 |
|---|---|---|
| 청약 후보·공시 찾기 | 조회 기간 | KIS 청약 일정, 마감순 분석 대상, 로컬 PDF 목록에 등록된 각 회사의 보고서명·접수일·접수번호. PDF 미확보도 명시한다. 기간 시작 전에 청약을 시작해 기간 안에 마감하는 종목도 포함한다. |
| 공시 근거 읽기 | 모델이 선택한 접수번호와 확인할 항목 | 원문의 표 제목, 행·열, 단위, 수치, 공시 링크. 최초·정정·발행조건확정 신고서를 구분하고, 확약률에는 신청 기준인지 배정 기준인지 표시한다. 공시 PDF를 로컬 다국어 모델로 임베딩해 접수번호 안에서 관련 페이지를 검색하고, 원문 표와 다음 쪽의 합계를 대조한다. 답변 근거에는 PDF 실제 쪽 번호와 DART 링크를 붙인다. |
| 직전 공모주 첫날 흐름 조회 | 분석 기준 시점 | 코스피·코스닥 일반기업 IPO 중 첫날 종가가 공개된 직전 3곳의 시장, 상장일, 공모가, 시가, 종가. 공모가 대비 시가와 시가 대비 종가의 등락률을 각각 계산한다. |

기준 시점을 결과에 표시한다. 과거 청약을 재현할 때는 당시 공개된 근거를 사용하고 배정 후 검산은 별도로 표시한다. 최근 IPO 흐름은 시장 상황을 설명하는 데 쓰며, 종목별 손익 시나리오에는 같은 상승률을 적용한다. 인증키는 실행 프로그램에서 관리하고 실행 기록에 담지 않는다. ## 종목별 판정

1. **균등 참여 또는 패스.** 기관의 제시가격 분포·확약 신청과 확정 공모가를 대조한다. 이어 상장일에 매도 가능한 기존 주주의 물량과 확인 가능한 취득가를 살핀다. 최소 청약 수량과 수수료까지 고려한다. 가격 또는 기존 주주 물량 중 하나만으로도 패스 근거가 충분하면 `청약 안 함`으로 종료하고 결정적인 수치와 표 위치를 제시한다.
2. **비례 한 주의 추가 손익.** 균등 참여 근거가 충분하면 종목별 청약단위에 맞는 신청 수량을 사용한다. 최소 청약에 이미 묶이는 증거금과 공통 청약 수수료는 추가 비용에서 제외한다. 배정 전에는 '비례 1주 추가 배정 가정'을, 배정 후 검산에는 확인된 신청 수량별 실제 배정 주수를 표시한다.
3. **최종 선택.** 공모가 대비 0%, +20%, +50% 매도가에서 추가 손익을 비교한다. 연습용 기준인 +20%에서 추가 손익이 양수면 `비례까지`, 0원 이하면 `균등만`이다. 필요한 증거금이나 배정 근거가 부족하면 해당 단계만 `판단 보류`로 남긴다.

비례 계산은 일반 Python 함수로 구현한다. 자금 비용은 자기자금 연 3% 단리이며 마감일에 신청한 것으로 가정한다. 결과표에 '매도 비용 제외'를 표시한다.

```text
추가 증거금 = (비례를 포함한 신청 수량 − 최소 청약 수량) × 공모가 × 증거금률
자금 비용 = 추가 증거금 × 0.03 × (환불일 − 청약 마감일의 달력 일수) / 365
추가 손익 = 추가 배정 주수 × (시나리오 매도가 − 공모가) − 자금 비용
주당 손익분기 매도가 = 공모가 + 자금 비용 / 추가 배정 주수  (추가 배정 주수가 양수일 때)
```

## 구현 검증과 제출

- **PDF 근거 검색.** 네 회사의 PDF 489쪽을 로컬에 색인했다. 옵토닉스의 확약 신청수량을 질의하면 첫 결과는 PDF 34쪽의 표 제목이고, 이어지는 35쪽의 합계 열에서 확약 106,196,000주 / 전체 신청 1,889,842,000주 = 5.62%를 재현했다. PDF 뷰어의 파일 쪽 번호를 기준으로 한다. [옵토닉스 공시](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20261029000504)
- **기간 비교.** 2026년 11월 2~6일 KIS 실전 조회에서 6곳을 확인했다. 상세 분석 대상이 동원파츠·바로팜·넥스아이 순서인지, 모델이 공시 목록에서 적절한 원문을 골랐는지 확인한다.
- **정보 부족.** 최종 배정 결과 공개 전 시점을 지정해 실제 비례 배정 주수를 묻는다. 확인 가능한 청약 조건, 조건부 추정치, 당시 알 수 없는 결과를 구분하면 통과다.
- **다른 호출 경로.** 같은 기간의 청약 일정만 요청한다. 후보와 일정을 반환한 뒤 종료하는지 본다.

세 유형을 실제 모델과 공개 API로 각각 한 번 이상 실행한다. 요청, 기준 시점, 모델명, 턴 한도, 도구 순서·입력·결과, 최종 답변, 종료 이유, 실제 모델 호출 수, 실행 시간을 기록하고 사람이 목표 달성 여부와 근거를 적는다. 이 기록으로 표의 단위·확약 기준을 잘못 읽은 문제와 턴 부족 문제를 구별한다. 모델이나 한도를 바꿀 때는 동일 사례를 재실행해 전후를 비교한다.

KIS 일정 조회와 상장일 시세 연결은 실데이터로 확인했다. 2번 도구의 자료원은 DART 공개 PDF로 정한다. OpenDART 키 발급은 PDF 검색의 선행 조건이 아니다. 이번 실습 목록은 동원파츠·바로팜·넥스아이·옵토닉스의 발행조건확정 공시이며, 미등록 종목은 보류한다. 모델을 붙인 전체 에이전트 실행은 별도로 검증한다. 제출물은 개인 README, 실행 코드, 인증정보를 제거한 실행 기록이다. 개념 조사는 작성자가 별도로 정리한다. [5주차 과제 안내](../../../README.md)
